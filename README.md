## 🌟 Overview

**HealthVault** is a revolutionary health data management platform that combines **GitHub-like repository management** with **AI-powered health insights**. Store, organize, and analyze your medical reports securely while getting personalized health recommendations from Google's Gemini AI.

Think of it as **GitHub for your health records** 🏥 + **ChatGPT for medical advice** 🤖

### 🎯 Problem Statement

Managing personal health records is a mess:
- 📄 Medical reports scattered across emails, folders, and physical files
- 🔒 No secure way to share health data with doctors or family
- 🤔 Difficulty understanding complex medical reports
- 📊 No centralized view of health trends over time
- 🔐 Privacy concerns with cloud storage of sensitive medical data

### 💡 Solution

HealthVault provides a **secure, intelligent, and organized** way to manage health records:
- 📁 **Repository System**: Organize reports like code repositories (e.g., "Blood Tests 2024", "X-Rays", "Prescriptions")
- 🔐 **Military-Grade Encryption**: AES-256-GCM encryption for all files
- 🤖 **AI Health Assistant**: Powered by Gemini 2.0 for instant medical insights
- 🔗 **Controlled Sharing**: Share specific repositories with doctors or family members
- 📊 **Health Dashboard**: Real-time BMI tracking and AI-generated risk assessments
- 💬 **Interactive AI Chat**: Ask questions about your reports and get detailed explanations

## 🏗️ Architecture

### **System Architecture**

```
┌─────────────────────────────────────────────────────────────┐
│                        USER INTERFACE                        │
│  Next.js 16 • React 19 • Tailwind CSS • TypeScript         │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                    AUTHENTICATION LAYER                      │
│                Auth0 (OAuth 2.0 / OIDC)                     │
└─────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────┐
│                     API ROUTES (Next.js)                     │
│  • Repositories  • Files  • Health Analysis  • Sharing      │
└─────────────────────────────────────────────────────────────┘
         │                    │                    │
         ▼                    ▼                    ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   MongoDB    │    │ Cloudflare R2 │    │  Gemini AI   │
│  (Metadata)  │    │  (Encrypted   │    │  (Analysis)  │
│              │    │    Files)     │    │              │
└──────────────┘    └──────────────┘    └──────────────┘
```

### **Security Flow**

```
Upload Flow:
User → Auth Check → Encrypt (AES-256-GCM) → R2 + Metadata → MongoDB

Download Flow:
User → Auth Check → Fetch from R2 → Decrypt → Stream to User

AI Analysis Flow:
User → Auth Check → Decrypt File → Gemini API → AI Response → User
```

### **Database Schema**

```typescript
User {
  auth0Id, name, email, username, age, height, weight,
  bloodGroup, gender, picture, profileCompleted
}

Repository {
  ownerId, name, description, isPrivate,
  filesCount, totalSize, createdAt, updatedAt
}

File {
  ownerId, repositoryId, name, size, mimeType,
  fileType, description, r2Key, encryptedKey,
  uploadedAt
}

SharedAccess {
  repositoryId, sharedByUserId, sharedWithUserId,
  accessLevel, expiresAt, isActive
}
```

## � Installation

### **Prerequisites**
- Node.js 20+ and npm
- MongoDB database (local or Atlas)
- Auth0 account
- Cloudflare R2 bucket
- Google Cloud account (for Gemini API)
- Redis instance (Upstash recommended)

### **Quick Start**

1. **Clone the Repository**
```bash
git clone https://github.com/nerkoux/healthcbs.git
cd healthcbs
```

2. **Install Dependencies**
```bash
npm install
```

3. **Generate Encryption Key**
```bash
node generate-key.js
# Or manually:
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

4. **Configure Environment Variables**

Create `.env.local`:

```bash
# MongoDB Configuration
MONGODB_URI=mongodb+srv://username:password@cluster.mongodb.net/?appName=Cluster0

# Auth0 Configuration
AUTH0_SECRET=use_openssl_rand_base64_32_to_generate
AUTH0_BASE_URL=http://localhost:3000
AUTH0_ISSUER_BASE_URL=https://your-domain.auth0.com
AUTH0_CLIENT_ID=your_auth0_client_id
AUTH0_CLIENT_SECRET=your_auth0_client_secret
AUTH0_DOMAIN=your-domain.auth0.com
APP_BASE_URL=http://localhost:3000

# Cloudflare R2 Configuration
R2_ACCOUNT_ID=your_cloudflare_account_id
R2_ACCESS_KEY_ID=your_r2_access_key
R2_SECRET_ACCESS_KEY=your_r2_secret_key
R2_BUCKET_NAME=your_bucket_name
R2_PUBLIC_URL=https://your-account-id.r2.cloudflarestorage.com

# App Configuration
NEXT_PUBLIC_APP_URL=http://localhost:3000

# AES-256 Encryption Key (32 bytes base64)
ENCRYPTION_KEY=your_generated_encryption_key_from_step_3

# Email Configuration (Optional - for notifications)
RESEND_API_KEY=your_resend_api_key
EMAIL_FROM=HealthVault <noreply@yourdomain.com>

# Google Gemini AI Configuration
GEMINI_API_KEY=your_gemini_api_key

# Redis Configuration
REDIS_URL=rediss://default:password@host:port
```

5. **Run Development Server**
```bash
npm run dev
```

6. **Open in Browser**
```
http://localhost:3000
```

### **Production Deployment**

1. **Build the Application**
```bash
npm run build
```

2. **Start Production Server**
```bash
npm start
```

3. **Deploy to Vercel** (Recommended)
```bash
vercel --prod
```

## 📱 Usage

### **For Patients**

1. **Sign Up / Login**
   - Click "Login" and authenticate via Auth0
   - Complete your health profile (age, height, weight, blood group, gender)

2. **Create Repositories**
   - Click "New Repository"
   - Name it (e.g., "Blood Tests 2024", "Cardiology Reports")
   - Add optional description
   - Repositories are private by default

3. **Upload Medical Reports**
   - Open a repository
   - Click "Upload File"
   - Select file type (Blood Test, X-Ray, MRI, etc.)
   - Add optional description
   - Files are encrypted automatically

4. **Get AI Insights**
   - Click "AI Assistant" in any repository
   - Select files to analyze
   - Ask questions like:
     - "What does this blood test indicate?"
     - "Are my cholesterol levels normal?"
     - "What diet should I follow based on these reports?"
   - Receive detailed, personalized responses

5. **View Health Dashboard**
   - See your BMI and health metrics
   - Review AI-generated risk assessments
   - Get personalized recommendations

6. **Share with Doctors**
   - Click "Share" on a repository
   - Enter doctor's username or email
   - Set access level (Read/Write/Admin)
   - Optional: Set expiration date
   - Revoke access anytime

### **For Healthcare Professionals**

1. **Receive Shared Access**
   - Patient shares repository with you
   - Access appears in "Shared with Me"

2. **Review Patient Records**
   - View all files in shared repositories
   - Download encrypted reports (auto-decrypted)
   - See patient's health profile

3. **Generate Health Summary**
   - Click on patient's profile
   - AI generates comprehensive medical summary
   - Export for consultations

4. **Collaborate**
   - Add notes and recommendations
   - Upload new reports (if Write access)
   - Communicate via AI chat

## � Security

HealthVault implements **defense-in-depth** security architecture:

### **Encryption**

- **Algorithm**: AES-256-GCM (Galois/Counter Mode)
- **Key Size**: 256 bits (32 bytes)
- **IV**: 96 bits (12 bytes) - randomly generated per file
- **Authentication Tag**: 128 bits (16 bytes) - ensures integrity
- **Key Storage**: Environment variable (never in database)

**Storage Format:**
```
[IV (12 bytes)] + [Auth Tag (16 bytes)] + [Ciphertext (variable)]
```

### **Authentication & Authorization**

- **Auth0 Integration**: Industry-standard OAuth 2.0 / OpenID Connect
- **Session Management**: Secure HTTP-only cookies
- **Token Validation**: JWT verification on every request
- **MFA Support**: Multi-factor authentication available

### **Access Control**

- **User Isolation**: Users can only access their own files
- **Repository-Level Permissions**: Read, Write, Admin levels
- **File Ownership Validation**: Backend verifies every operation
- **Shared Access Control**: Granular sharing with expiration

### **Data Protection**

- **Zero-Knowledge Architecture**: Server never stores plaintext
- **Encrypted at Rest**: Files encrypted before R2 upload
- **Encrypted in Transit**: HTTPS everywhere
- **Encrypted Backups**: R2 versioning preserves encryption

### **API Security**

- **Rate Limiting**: Prevent abuse (via Redis)
- **Input Validation**: TypeScript + runtime validation
- **SQL Injection Protection**: Mongoose ODM
- **XSS Protection**: React escaping + Content Security Policy
- **CSRF Protection**: Next.js built-in

### **Security Best Practices**

✅ **DO:**
- Rotate `ENCRYPTION_KEY` periodically
- Use HTTPS in production
- Enable Auth0 MFA
- Monitor access logs
- Implement rate limiting
- Regular security audits
- Use environment-specific keys

❌ **DON'T:**
- Commit `.env.local` to Git
- Share encryption keys
- Use same keys across environments
- Expose R2 bucket publicly
- Store sensitive data in client

### **Compliance**

- **HIPAA Ready**: Encryption and access controls support HIPAA compliance
- **GDPR Compatible**: Right to deletion, data export, access logs
- **SOC 2**: Infrastructure follows SOC 2 principles
- **Data Residency**: Choose MongoDB region for compliance

## 📚 API Documentation

### **Authentication**
All endpoints require Auth0 session (except auth routes)

### **Endpoints**

#### **Repositories**

**Create Repository**
```http
POST /api/repositories
Content-Type: application/json

{
  "name": "Blood Tests 2024",
  "description": "Annual blood work results",
  "isPrivate": true
}

Response: 201 Created
{
  "repository": { ... }
}
```

**List Repositories**
```http
GET /api/repositories

Response: 200 OK
{
  "owned": [ ... ],
  "shared": [ ... ]
}
```

**Get Repository Details**
```http
GET /api/repositories/{id}

Response: 200 OK
{
  "repository": { ... }
}
```

#### **Files**

**Upload File**
```http
POST /api/upload
Content-Type: multipart/form-data

file: <binary>
repositoryId: "repo_id"
fileType: "blood-test"
description: "Q4 2024 comprehensive panel"

Response: 201 Created
{
  "success": true,
  "file": { ... }
}
```

**List Files**
```http
GET /api/repositories/{id}/files

Response: 200 OK
{
  "files": [ ... ]
}
```

**Download File**
```http
GET /api/download?fileId={id}

Response: 200 OK (Binary stream)
```

#### **AI Analysis**

**Analyze Health Profile**
```http
POST /api/health/analyze

Response: 200 OK
{
  "analysis": {
    "bmi": 24.5,
    "bmiCategory": "Normal weight",
    "riskAssessment": [ ... ],
    "recommendations": [ ... ]
  }
}
```

**AI Chat with Files**
```http
POST /api/repositories/{id}/chat
Content-Type: application/json

{
  "message": "What does my blood test indicate?",
  "fileIds": ["file1", "file2"]
}

Response: 200 OK
{
  "response": "Based on your blood test results...",
  "timestamp": "2024-11-09T10:00:00Z"
}
```

#### **Sharing**

**Share Repository**
```http
POST /api/repositories/{id}/share
Content-Type: application/json

{
  "username": "doctor_smith",
  "accessLevel": "read"
}

Response: 200 OK
{
  "success": true
}
```

**List Shared Access**
```http
GET /api/repositories/{id}/share

Response: 200 OK
{
  "sharedAccess": [ ... ]
}
```

**Revoke Access**
```http
DELETE /api/repositories/{id}/share?accessId={accessId}

Response: 200 OK
{
  "success": true
}
```
